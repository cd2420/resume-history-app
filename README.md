## 누구를 위한 에이전트인가

**프로젝트 단위로 일하는 경력직 직장인**, 그중 1차 사용자는 이직을 준비하는 개발자입니다.

- 평소에는 경력을 기록하지 않다가 채용공고가 뜨면 기억에 의존해 이력서를 고칩니다. 그래서 작업을 통째로 빠뜨리고, **왜·어떻게** 했는지가 남아 있지 않아 성과를 제대로 쓰지 못합니다.
- 퇴근 후에는 지쳐서 스스로 기록하지 않습니다. 기록에 쓸 수 있는 시간은 최대 10분입니다.
- 기록은 휴대폰(텔레그램)으로, 이력서는 PC에서 씁니다.

## 어떤 업무를 대신하는가

1. **먼저 물어보기**: 사용자가 고른 시간(매일 0~23시 중 1시간 단위)에 텔레그램으로 오늘 한 일을 먼저 묻습니다. 질문은 3개뿐입니다(한 일 / 직접 맡거나 결정한 것과 이유 / 결과). 2·3번은 버튼으로 건너뛸 수 있습니다.
2. **기밀 가리기**: 답을 받을 때마다 고객사명·내부 시스템명·절대 수치 같은 기밀을 일반화하고, 사용자가 카드로 확인한 뒤에만 저장합니다. 보낸 원문은 저장하지 않습니다.
3. **책장에 정리하기**: 프로젝트는 **책**, 일일 기록은 책 속 **페이지**, 분류는 사용자가 이름 붙이는 **칸**입니다. 기술·역량 태그를 붙여 두어, 이력서를 쓸 때 공고 요건(예: "대용량 트래픽")에 맞는 기록을 키워드·태그·기간으로 바로 찾습니다.
4. **이력서 재료로 꺼내기**: 프로젝트가 끝나면 쌓인 기록으로 **STAR**(상황·과제·행동·결과)를 정리합니다. 각 항목의 근거 기록을 보여 주고, 기록에 없는 수치는 지어내지 않고 **빈칸**으로 남깁니다.

## 지금까지 만든 것

운영 배포(Vercel + Supabase + OpenAI)까지 마쳤고, 가입부터 STAR 저장까지 한 흐름이 작동합니다. 아래 화면은 데모 모드(가짜 데이터)로 찍었습니다.

### 텔레그램 기록 (질문 3개 → 기밀 일반화 → 확인 카드 → 저장)

- 정각 알림(Supabase `pg_cron`)이나 `/record`로 기록 세션이 열립니다.
- 답마다 기밀을 일반화합니다. 예: "A은행 결제승인 API" → "대형 금융사 결제 승인 API". 보낸 원문은 저장하지 않습니다.
- 질문은 고정 문구라 AI를 쓰지 않고, 기록 세션 밖의 메시지에도 AI를 호출하지 않습니다(토큰 낭비 방지).
- 그날 이미 기록했으면 알림을 건너뜁니다. 책이 없으면 이름만 보내도 책이 생기고, `/project`나 카드의 [프로젝트 변경]으로 책을 바꿉니다.

### STAR 정리

- 책 화면에서 프로젝트를 끝내면 STAR 초안을 만들고, 항목마다 근거 기록과 빈칸을 보여 줍니다.
- 기록에 없는 수치는 `[빈칸: 개선 전후 응답 시간]`처럼 남깁니다. 근거 날짜를 누르면 그 기록으로 이동합니다.
- AI 원본과 저장본을 함께 남겨, PRD 성공 지표인 "수정 없이 저장한 비율"을 잴 수 있습니다.
- 끝난 책은 봇의 프로젝트 목록에서 빠지고, 봇은 다음 기록 때 새 프로젝트를 묻습니다.

### 현재 상태

- 무료 사용 한도: 하루 기록 세션 1회, 하루 STAR 1회, 책당 STAR 1번. AI 비용 관리를 위한 것이며 이후 유료로 확장할 예정입니다.
- 테스트: 단위 테스트 155개 통과, 데모 E2E 6개 중 4개 통과(실패 2개는 아래 '막힌 부분' 참고).
- 보안: 모든 테이블에 RLS를 적용했습니다. 텔레그램 봇과 정시 알림만 secret 키를 쓰고, 이 경로에서는 사용자를 텔레그램 연결 정보로만 정합니다.

## 막힌 부분

- **OpenAI API 키 만료로 실제 AI 결과를 검증하지 못함**: STAR 생성이 502로 실패해 원인을 추적했더니 `401 expired_secret_key`였습니다. 실제 모델이 빈칸을 남기는지, 수치를 지어내지 않는지는 가짜 AI로만 확인했습니다. 새 키를 발급해 운영에서 다시 확인해야 합니다.
- **정각 알림 한 바퀴를 운영에서 끝까지 확인하지 못함**: `pg_cron`이 매 정각 알림 API를 호출하는 것까지는 로그로 확인했습니다. 알림 → 질문 3개 → 저장 → 책장까지 실제 텔레그램으로 이어지는 흐름은 아직 끝까지 보지 못했습니다.
- **다른 사용자를 받을 준비가 안 됨**
  - Supabase 기본 메일은 발송량과 수신 대상이 제한돼, 다른 사람은 인증 메일을 받지 못할 수 있습니다. 외부 SMTP 연결이 필요합니다.
  - 메일 인증 링크를 누르면 세션이 만들어지지 않아 다시 로그인해야 합니다.
  - Supabase 무료 프로젝트는 활동이 없으면 일시 정지됩니다(실제로 한 번 정지돼 봇이 500 오류를 냈습니다).
- **웹에서 쓴 기록에는 태그가 붙지 않음**: AI로 태그를 채우는 버튼은 비용 때문에 없앴습니다. 대신 키워드 사전(관리자가 관리 + 사용자가 입력한 태그를 수집, 승인한 것만 공용)으로 붙이는 방식을 [계획](.claude/plans/web-log-dictionary-tags.plan.md)만 세웠습니다. 개발자 외 직군(기획·디자인·비IT)까지 다루려면 사전을 직군별로 나눠야 해서 범위를 정하는 중입니다.
- **빠진 맥락 되묻기 (4단계, 아직 시작 전)**: 매일 질문 3개로는 기록이 비는 경우를 메우는 기능입니다.
  - **빠진 것만 한 번 되묻기**: 매일 기록에서는 2번(직접 맡은 일과 이유)·3번(결과·수치) 질문을 건너뛸 수 있습니다. 그래서 프로젝트가 끝나 STAR를 만들 때 "캐시를 고른 이유", "개선 전후 응답 시간" 같은 **빈칸**이 생깁니다. 지금은 빈칸을 보여 주기만 합니다. 이 기능이 생기면 프로젝트가 끝날 때 빈칸이 있는 경우에만, 봇이 텔레그램으로 그 빈칸 항목을 **한 번** 묻고 답을 STAR에 채워 넣습니다. AI 호출 비용을 줄이려고 매일이 아니라 프로젝트 종료 때 한 번만 묻습니다.
  - **사흘 무응답이면 질문을 가볍게**: 정각 알림에 사흘 연속 답하지 않으면, 다음 알림은 질문 3개 대신 "오늘 한 일 한 줄만" 같은 더 짧은 질문으로 바꿔 기록이 끊기지 않게 합니다.
  - **커밋 메시지 붙여넣기**: 개발자가 그날의 커밋 메시지를 봇에 붙여넣으면, 기밀을 가리고 요약해 그날 기록으로 넣습니다. 회사 저장소에 직접 연결하지 않고 사용자가 붙여넣은 글만 씁니다.
- **그 밖에 남은 것**: 텔레그램에서 "프로젝트 끝" 알리기(지금은 웹에서만), 책장 디자인 개편 뒤 E2E 2개의 화면 선택자 갱신, 약관 문구 법률 검토, 유료 결제.

## 나의 에이전트 활용법

Claude Code를 기획부터 운영까지 함께 일하는 동료 개발자로 쓰고, 저는 결정과 검수를 맡았습니다.

- **기획부터 문서로**: 아이디어를 바로 코딩하지 않고 PRD(문제·근거·가설·성공 지표·범위·마일스톤)를 먼저 쓰게 했습니다. 기능을 추가할 때마다 PRD의 범위·미결 질문·위험을 갱신해, 저장소만 봐도 왜 이렇게 만들었는지 알 수 있게 했습니다.
- **규칙은 파일로 고정**: `CLAUDE.md`에 구조와 금지사항(앱에서 DB 직접 접속 금지, React Router v7 고정, 원문 저장 금지 등)을 적고, 메모리에 "답은 한국어로" 같은 선호를 남겨 세션이 바뀌어도 같은 기준으로 일하게 했습니다.
- **테스트 먼저, 화면으로 확인**: 기능마다 실패하는 테스트를 먼저 쓰게 하고(RED → GREEN), 데모 모드(가짜 DB·AI·텔레그램)로 E2E와 화면 캡처를 돌려 실제 흐름을 확인했습니다. 이 README의 화면도 그렇게 찍었습니다.
- **운영 연결과 장애 추적**: Supabase·Vercel MCP로 마이그레이션 적용, 데이터 확인, 런타임 로그 조회를 맡겼습니다. 실제로 찾은 원인은 다음과 같습니다.
  - 봇 500 오류 → 로그에서 환경변수 6개 누락 발견
  - 다시 500 오류 → 테이블 없음(마이그레이션 미적용) 발견
  - STAR 502 오류 → OpenAI 키 만료 발견
- **병렬로 일 나누기**: 큰 작업(PRD 갱신)을 하는 동안 작은 기능(로그인 이메일 저장)은 백그라운드 서브에이전트에 맡기고, 끝나면 결과를 검수해 합쳤습니다.
- **훅으로 안전장치**: 파일을 고치기 전에 영향 범위(누가 import하는지, 어떤 API가 바뀌는지)를 먼저 밝히게 하는 훅과, 디자인 시스템에서 벗어나면 경고하는 훅을 걸어 두었습니다.
- **결정은 제가, 근거는 에이전트가**: 비용·보안이 걸린 선택은 에이전트가 근거와 대안을 내고 제가 정했습니다.
  - 텔레그램은 무료이고 비용은 OpenAI뿐이라는 분석을 보고, 무료 한도를 하루 1회로 정했습니다.
  - 태그를 AI 대신 키워드 사전으로 붙이기로 했고, 사용자 태그를 공용 사전에 그대로 넣으면 기밀이 퍼진다는 지적을 받아 "승인한 것만 공용"으로 설계했습니다.
- **커밋 정리**: 섞여 있던 변경을 기능별 7개 커밋으로 나누게 하고, 커밋마다 타입 검사와 테스트가 통과하는지 확인한 뒤 push했습니다.
- **평소 업무**: 코드 저장소와 개인 지식 베이스(Obsidian)에서도 같은 방식으로, 먼저 찾고 근거를 대게 한 뒤 제가 결정하는 생각 파트너로 씁니다.

## 개발

```bash
npm install
npm run dev        # http://localhost:5173 (설정값이 없으면 데모 모드)
npm run build
npm run typecheck
npm test           # 단위 테스트
npm run test:e2e   # Playwright E2E
```

- React Router v7 프레임워크 모드(SSR) + Vite + Tailwind CSS v4 / Supabase(Postgres·Auth·RLS·`pg_cron`) / OpenAI Responses API / Telegram Bot API.
- 환경변수 목록은 [`.env.example`](.env.example), 개발 규칙과 구조는 [`CLAUDE.md`](CLAUDE.md)에 있습니다.
- `main`에 push하면 Vercel 운영에 자동 배포됩니다(`react-router.config.ts`의 [`@vercel/react-router`](https://vercel.com/docs/frameworks/frontend/react-router) 프리셋).
