## 누구를 위한 에이전트인가
**프로젝트 단위로 일하는 경력직 직장인**, 그중 1차 사용자는 이직을 준비하는 개발자입니다.
- 평소에는 경력을 기록하지 않다가 채용공고가 뜨면 기억에 의존해 이력서를 고칩니다. 그래서 작업을 통째로 빠뜨리고, **왜·어떻게** 했는지가 남아 있지 않아 성과를 제대로 쓰지 못합니다.
- 퇴근 후에는 지쳐서 스스로 기록하지 않습니다. 기록에 쓸 수 있는 시간은 최대 10분입니다.
- 기록은 휴대폰(텔레그램)으로, 이력서는 PC에서 씁니다.

## 어떤 업무를 대신하는가
1. **먼저 물어보기**: 사용자가 고른 시간(매일 0~23시 중 1시간 단위)에 텔레그램으로 오늘 한 일을 먼저 묻습니다. 질문은 3개뿐입니다(한 일 / 직접 맡거나 결정한 것과 이유 / 결과). 2·3번은 버튼으로 건너뛸 수 있습니다.
2. **기밀 가리기**: 답을 받을 때마다 고객사명·내부 시스템명·절대 수치 같은 기밀을 일반화하고, 사용자가 카드로 확인한 뒤에만 저장합니다. 보낸 원문은 저장하지 않습니다.
3. **책장에 정리하기**: 프로젝트는 **책**, 일일 기록은 책 속 **페이지**, 분류는 사용자가 이름 붙이는 **칸**입니다. 기술·역량 태그를 붙여 두어, 이력서를 쓸 때 공고 요건(예: "대용량 트래픽")에 맞는 기록을 키워드·태그·기간으로 바로 찾습니다.
4. **이력서 재료로 꺼내기**: 프로젝트가 끝나면 쌓인 기록으로 **STAR**(상황·과제·행동·결과)를 정리합니다. 각 항목의 근거 기록을 보여 주고, 기록에 없는 수치는 지어내지 않고 **빈칸**으로 남깁니다.

## 진행 상황 (2026-11-11 기준)

### 지금 되는 것
- **가입·동의**: 웹 가입, 이메일 인증, 개인정보·국외 이전 동의. 약관 본문과 버전은 DB에서 관리하고, 개정되면 다시 동의받습니다.
- **텔레그램 연결**: 책장 위 '시작하기' 카드에서 별도 동의 후 딥링크로 연결하고, 알림 시간을 고릅니다(기본 21시). 텔레그램에서 돌아오면 연결 상태가 자동으로 반영됩니다.
- **매일 기록**: 정각 알림(Supabase `pg_cron`)이나 `/record`로 기록 세션이 열리고, 질문 3개 → 기밀 일반화 → 확인 카드 → 저장까지 진행됩니다. 세션 밖의 메시지에는 AI를 쓰지 않습니다. 그날 이미 기록했으면 알림을 건너뜁니다.
- **프로젝트 관리(봇)**: 책이 없으면 이름만 보내도 책이 생기고 바로 질문이 이어집니다. `/project`로 바꾸고, 카드의 [프로젝트 변경]으로 이번 기록만 다른 책에 넣을 수 있습니다.
- **웹 책장**: 칸 만들기·이름 바꾸기·순서 바꾸기·지우기, 책을 칸으로 옮기기, 월별 목차로 읽기, 키워드·태그·기간 검색, 기록 수정·삭제·태그 편집, 웹에서 기록 직접 쓰기. 책을 열 때 로딩 표시.
- **STAR 정리**: 책 화면에서 프로젝트를 끝내면 STAR 초안을 만들고, 근거 기록·빈칸을 확인해 고친 뒤 저장합니다. 끝난 책은 봇의 프로젝트 목록에서 빠집니다.
- **계정**: 로그인 이메일 저장, 회원 탈퇴(모든 기록 삭제), 탈퇴 후 같은 텔레그램 계정의 당일 재연결 제한.
- **무료 사용 한도**: 하루 기록 세션 1회, 하루 STAR 1회, 책당 STAR 1번. AI 호출 비용을 줄이기 위한 것으로, 이후 유료로 늘릴 예정입니다.
- **운영**: Vercel(운영 배포) + Supabase(Postgres·인증·RLS) + OpenAI Responses API(`store: false`). 설정값이 없는 로컬·프리뷰는 데모 모드(메모리 데이터·가짜 AI·웹 봇 시뮬레이터)로 동작합니다.

### 아직 안 되는 것
- **운영에서 끝까지 확인하지 못한 것**: 정각 알림부터 질문 3개, 저장, 책장까지 한 바퀴. 실제 OpenAI로 만든 STAR 품질(빈칸·근거·수치를 지어내지 않는지).
- **텔레그램에서 "프로젝트 끝" 알리기**: 지금은 웹 책 화면에서만 STAR를 만듭니다.
- **빠진 맥락 되묻기 (4단계, 아직 시작 전)**: 매일 질문 3개로는 기록이 비는 경우를 메우는 기능입니다. 세 가지로 이루어집니다.
  - **빠진 것만 한 번 되묻기**: 매일 기록에서는 2번(직접 맡은 일과 이유)·3번(결과·수치) 질문을 건너뛸 수 있습니다. 그래서 프로젝트가 끝나 STAR를 만들 때 "캐시를 고른 이유", "개선 전후 응답 시간" 같은 **빈칸**이 생깁니다. 지금은 빈칸을 보여 주기만 합니다. 이 기능이 생기면 프로젝트가 끝날 때 빈칸이 있는 경우에만, 봇이 텔레그램으로 그 빈칸 항목을 **한 번** 묻고 답을 STAR에 채워 넣습니다. 빈칸이 없으면 묻지 않고, AI 호출 비용을 줄이려고 매일이 아니라 프로젝트 종료 때 한 번만 묻습니다.
  - **사흘 무응답이면 질문을 가볍게**: 정각 알림에 사흘 연속 답하지 않으면, 다음 알림은 질문 3개 대신 "오늘 한 일 한 줄만" 같은 더 짧은 질문으로 바꿔 기록이 끊기지 않게 합니다.
  - **커밋 메시지 붙여넣기**: 개발자가 그날의 커밋 메시지를 봇에 붙여넣으면, 기밀을 가리고 요약해 그날 기록으로 넣습니다. 회사 저장소에 직접 연결하지 않고 사용자가 붙여넣은 글만 씁니다.
  - 기획 문서(PRD)의 "Delivery Milestones" 4번 항목이며, 아직 구현 계획도 세우지 않았습니다.
- **웹 기록 자동 태그**: 웹에서 쓴 기록은 태그가 비어 있습니다. 키워드 사전(관리자 관리 + 사용자 태그 수집) 방식으로 계획만 세웠습니다([계획서](.claude/plans/web-log-dictionary-tags.plan.md)).
- **사용성 남은 것**: 메일 인증 링크를 누르면 다시 로그인해야 함, `/` 없이 보낸 `project` 명령 인식, 첫 화면에서 책장의 가치 보여 주기.
- **다른 사용자 받기 전 준비**: 외부 메일 서버(SMTP) 연결, 약관 문구 법률 검토.
- **결제**: AI 사용 한도를 늘리는 유료 기능은 아직 없습니다.
- **범위 밖**: 이력서 전체 생성·공고 맞춤 수정, 카카오톡, 모바일 앱, 회사 시스템(Jira·GitLab) 자동 수집.

## 개발

```bash
npm install
npm run dev        # http://localhost:5173 (설정값이 없으면 데모 모드)
npm run build
npm run typecheck
npm test           # 단위 테스트
npm run test:e2e   # Playwright E2E
```

- React Router v7 프레임워크 모드(SSR) + Vite + Tailwind CSS v4.
- 환경변수 목록은 [`.env.example`](.env.example), 개발 규칙과 구조는 [`CLAUDE.md`](CLAUDE.md)에 있습니다.
- `main`에 push하면 Vercel 운영에 자동 배포됩니다(`react-router.config.ts`의 [`@vercel/react-router`](https://vercel.com/docs/frameworks/frontend/react-router) 프리셋).
