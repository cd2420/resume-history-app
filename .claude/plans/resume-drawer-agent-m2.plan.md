# Plan: 이력서랍 — 책장 열어보기

**Source PRD**: `.claude/prds/resume-drawer-agent.prd.md`
**Selected Milestone**: 2 — 책장 열어보기
**Complexity**: Medium (DB 변경 1개, AI 출력 확장, 웹 화면 3개 재구성)

## Summary
웹 첫 화면을 **책장**으로 바꾼다. 프로젝트는 표지가 보이게 꽂힌 **책**이고, 책장의 **칸**은 사용자가 이름 짓는 분류다("A사", "개인 프로젝트" 등). 텔레그램으로 만든 새 책은 '새로 꽂힌 책' 칸에 들어가고, 웹에서 칸을 옮긴다. 책을 열면 **월별 목차 + 날짜순 기록**을 읽는다. 위쪽 검색창에서 키워드·기술 태그·기간으로 찾으면 결과를 **기록(페이지) 단위**로 책 제목과 함께 보여 준다. 기술·역량 태그는 기록을 저장할 때 AI가 붙이고, 웹에서 고칠 수 있다.

## 인터뷰로 정한 결정
| 항목 | 결정 |
|---|---|
| 비유 | 프로젝트 = 책, 기록 = 날짜순 책 내용, 칸 = 사용자 분류(회사로 한정 안 함) |
| 진열 | 표지 진열(서점 평대). 장식용 실물 효과(나무 질감·3D 넘김)는 쓰지 않음 |
| 표지 정보 | 제목, 기간(첫 기록~마지막 기록), 대표 태그 3개, 진행 중 배지 |
| 칸 규칙 | 책 한 권은 한 칸에만. 여러 분류에 걸치는 기준은 태그로 |
| 새 책 위치 | '새로 꽂힌 책' 칸(맨 위). 웹에서 원하는 칸으로 옮김 |
| 태그 | 저장할 때 AI가 자동으로 붙임 + 웹에서 수정 |
| 찾기 | 키워드 검색, 기술 태그 필터, 기간 필터 |
| 검색 결과 | 기록 단위, 책 제목·날짜와 함께, 검색어 강조 |
| 책 읽기 | 월별 목차 + 이어서 스크롤 |
| 기기 | PC 우선, 휴대폰은 칸을 접는 섹션 + 가로 스크롤 |

## 기본값으로 정한 것 (바꾸려면 알려 주세요)
| 항목 | 기본값 | 이유 |
|---|---|---|
| 진행 중 | **현재 프로젝트**(봇이 기록을 넣는 책) 1권에만 배지. "완결"은 M3의 "프로젝트 끝"과 함께 | M2에 완결 신호가 없음 |
| 칸 안 책 순서 | 진행 중 → 마지막 기록이 최근인 순 | 지금 쓰는 책이 앞에 |
| 칸 순서 바꾸기 | ↑↓ 버튼 (드래그 없음) | 휴대폰·키보드에서도 동작 |
| 책 옮기기 | 책 화면의 "칸으로 이동" 선택 메뉴 | 같은 이유 |
| 칸 삭제 | 칸 안의 책은 '새로 꽂힌 책'으로 돌아감 | 책이 사라지지 않음 |
| 태그 필터 | 한 번에 태그 1개 | AND/OR 혼동 없음. 공고 요건 하나씩 찾는 용도 |
| 기간 필터 | 시작 월 ~ 끝 월 (`<input type="month">`) | 휴대폰 기본 선택기 |
| 검색 조건 | URL 쿼리(`?q=&tag=&from=&to=`) | 뒤로 가기·북마크가 동작 |
| 태그 개수·길이 | 기록당 0~5개, 태그당 1~30자 | 표지·필터가 넘치지 않음 |
| 태그 표기 흔들림 | AI에 사용자의 기존 태그 목록을 주고 재사용하게 함. 대소문자만 다른 태그는 하나로 | "Kafka"/"kafka" 분산 방지 |
| 기존 기록 태그 | 책장의 "태그 없는 기록 N개 채우기" 버튼, 한 번에 20개 | 사용자가 직접 실행, 비용 예측 가능 |
| 설정 위치 | 텔레그램 연결·알림 시간은 `/drawer/settings`로 분리 | 책장을 첫 화면으로 |

## 기술 결정
| 항목 | 결정 | 근거 |
|---|---|---|
| 칸 저장 | 새 테이블 `shelves(id, user_id, name, position)`, `projects.shelf_id` nullable. null = '새로 꽂힌 책'(가상 칸) | 봇은 칸을 몰라도 됨 |
| 태그 저장 | `daily_logs.tags text[]` + GIN 인덱스, `pending_logs.tags text[]` | 기록당 태그 몇 개, 조인 없이 필터(`@>`) |
| 태그 생성 | 기존 일반화 호출의 구조화 출력에 `tags` 필드 추가. 추가 호출 없음 | 비용 그대로 |
| 기존 기록 태그 | 일반화된 기록 본문만 보내는 별도 호출(`suggestTags`), `store: false` | 원문은 이미 없음 |
| 한국어 검색 | `position(lower(q) in lower(content)) > 0`. 전문 검색(FTS) 안 씀 | Postgres 기본 FTS에 한국어 파서가 없음. 사용자당 기록 수백 건이라 인덱스 없이 충분. `%`·`_` 이스케이프 문제도 없음 |
| 검색·책장 조회 | `security invoker` RPC 2개(`drawer_bookshelf`, `drawer_search_logs`)로 RLS 그대로 | 여러 테이블 조인과 집계를 한 번에 |
| 데모 모드 | `DemoStore`·`DrawerWebStore`에 같은 기능 추가 | 프리뷰에서 바로 확인 |
| 검색 폼 | `<Form method="get">` + `useSearchParams` | 공식 패턴, JS 없이도 동작 |

## 데이터 변경 (마이그레이션 1개)
| 대상 | 변경 |
|---|---|
| `shelves` | 신규. `name` 1~50자, `position int`, `unique(id, user_id)`, RLS 소유자 전용 |
| `projects` | `shelf_id uuid` 추가, FK `(shelf_id, user_id) → shelves on delete set null (shelf_id)` |
| `daily_logs` | `tags text[] not null default '{}'`, `cardinality(tags) <= 5` 체크, GIN 인덱스 |
| `pending_logs` | `tags text[] not null default '{}'` |
| `drawer_save_pending_log` | 카드의 태그를 기록으로 복사(수정해서 저장해도 유지) |
| `drawer_bookshelf()` | 책별 칸·제목·첫/마지막 기록일·기록 수·대표 태그 3개 |
| `drawer_search_logs(q, tag, from, to)` | 조건에 맞는 기록 + 책 제목·칸 이름. 최대 200건 |

## Risks
| Risk | Likelihood | Mitigation |
|---|---|---|
| AI 태그 표기가 흔들려 같은 기술이 여러 태그로 나뉨 | High | 기존 태그 목록 재사용 지시, 대소문자 통합, 웹에서 수정 |
| 기존 기록 태그 채우기 비용 | Low | 한 번에 20개, 사용자가 실행, 일반화된 짧은 본문만 전송 |
| 칸이 많아지면 책장이 길어짐 | Medium | 칸 접기, 검색이 기본 진입점 |
| 기록이 많은 책의 화면이 무거움 | Low | 사용자당 수백 건 기준. 1000건 넘으면 월 단위로 나눠 불러오기 |
| M1 운영 설정 전이라 실데이터 검증 불가 | High | 데모 모드 + 로컬 Postgres로 검증, 운영 확인은 M1 Task 9와 함께 |
